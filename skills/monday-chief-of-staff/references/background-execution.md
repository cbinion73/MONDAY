# Scheduled chief-of-staff execution

Use this workflow during the existing morning preparation run, briefing, or
evening review. It implements Chris's 2026-09-20 request for behind-the-scenes
follow-through using ChatGPT/Codex, the installed plugin, and governed knowledge.
It now applies Chris's 2026-09-21 outcome-based delegation, not a preparation-only cap. Read the Constitution and monday-core/references/autonomy-ladder.md.
The scheduler must actually invoke a run; these instructions do not stay awake.

## Shared checkpoint and scope

Read `monday:Follow-Ups/Monday Execution State.md` through the governed service
before choosing work. It is a coordination record, not another project registry.
Keep project IDs and artifact links; do not duplicate full project histories.
Read `monday:Decisions/2026-09-21-outcome-based-delegation.md` for current authority; the 2026-09-20 background-operation note retains workflow history. A missing checkpoint is an explicit first-run condition, not permission
to invent assignments.

Within this workflow, read authorized sources, reconcile evidence, and advance
existing delegated outcomes through implementation and verification. Select
necessary next actions from current evidence; maintain owning records and
implementation subtasks without inventing new goals or Chris's commitments. Examples: an evidence inventory,
meeting preparation, draft decision brief, or an already-requested publication
package. Save preparation in the relevant approved workspace/vault, labeled as a
draft where appropriate. Preserve source files and Chris's voice.

Routine coordination covered by a delegation may proceed under the shared
authority rule. An old project title or inferred preference does not authorize
publication, spending, sensitive disclosure, significant commitments, destructive
changes, or production release. Specific calendar and collection controls remain.
Changing this workflow, other skills, or schedules is not a recurring mandate.

## Morning preparation

1. Read the checkpoint, open canonical tasks, and active project registry.
   Load only source notes and specialist skills needed for the selected work.
   Use the data checks below before treating any record as current.
2. Select one supported, useful next action: first resume an unfinished
   authorized artifact; otherwise use a confirmed deadline or recorded priority.
   A time-sensitive task needs source evidence, not an invented due date.
3. If its evidence is stale, try to refresh from its linked source and recent
   relevant records. Reading an old note today does not renew its evidence date.
   If still unresolved, produce a concise reconciliation artifact identifying
   facts, contradictions, and the smallest missing fact. Do not repeatedly
   regenerate that artifact when sources have not changed.
4. Execute the delegated work, inspect the resulting artifact, and read
   back any governed writes. Record what materially advanced. If the selected
   task is blocked, attempt another already-authorized independent item.
5. Save the checkpoint through `write_memory`, type `follow_up`, with:
   run time/timezone; objective and project/task ID; authorization/source;
   source evidence dates and availability; completed work and artifact links;
   verification; next concrete action; exact blocker and owner if known;
   which decision was last surfaced and when; automation ID.
   Retain open items, replacing resolved state rather than accumulating logs.
6. Finish the existing planner output contract as well. Source uncertainty
   must be visible in the derived plan. Do not force a priority to fill a page.

Keep each scheduled run bounded by available runtime, cost, and the selected
outcome. Do not stop solely because one artifact was prepared when safe useful
work remains. Checkpoint cleanly at runtime limits. Avoid broad corpus scans
and unlimited retry loops.
An unavailable source should not block unrelated permitted work.

## Briefing at 9:15

Read today's checkpoint and refresh today's relevant calendar data. Lead with
the real priority, then what Monday actually advanced, one material conflict,
and any decision Chris must make. Link the artifact. If preparation did not run
or is stale, say so and perform the useful authorized work within the briefing's runtime in this run.
Do not report missing preparation as completed background work. Do not repeat
the same blocker daily unless its evidence, consequence, or deadline changed.

## Evening closeout

Read today's checkpoint and relevant completion evidence before the diary.
Verify claimed artifacts; reconcile completed or blocked state through governed
writes within the approved scope. Carry forward the next action and any
unresolved source issue. Keep reflection separate from execution status.
Do not claim all chats were inspected or all work captured unless they were.

## Data checks

- Project registry owns operational status; linked notes provide evidence.
  Inspect `evidence_as_of` separately from `updated_at`. As a triage default,
  evidence older than 14 days or a passed review gate needs source refresh.
  This is a workflow threshold, not proof the project failed or stopped.
- Task list supplies existing assignments; a task record is not authorization
  for its external send/purchase/share step. Inspect the owning source.
- Outlook owns work events. Its bridge is a derived copy: inspect refresh time,
  coverage, timezone and source uncertainty before use. Expect a daily refresh;
  flag a copy older than 26 hours, a missing relevant day, or an unclear timezone.
- Cozi owns family events; use the governed read-only feed. Deduplicate
  occurrences, and do not assume a family member's event requires Chris's time.
- Google Work is a mirror. Cross-check matching occurrences when available.
  A disagreement is a source conflict: withhold affected times from definitive
  planning and calendar writes until the original source resolves it. Do not
  silently pick Google, subtract four hours, or duplicate both as appointments.
- Web research is for a specific current evidence gap, not routine news filler.
- File modification time, a successful tool call, or an OAuth scope does not
  prove current content, successful scheduling, or permission to act.
- On partial access, label the source partial and retain verified independent
  facts. Never interpret an unreadable calendar as free time.

## Retry and reporting

Before an action, re-read the checkpoint to avoid duplicate preparation. If a
matching run is in progress, do read-only work and avoid overlapping writes.
A note is not a transactional lock: if concurrent changes are visible, re-read
and merge the narrow update; do not overwrite another run's progress.

Record an unchanged blocker once; revisit after new evidence, a relevant source
refresh, or the next deliberate weekly review. Do not manufacture daily output.
A configured automation is not proof of a successful unattended run or phone
delivery. Report manual test, configured schedule, scheduler execution, and
notification delivery separately.

# Knowledge retrieval for useful work

Use this for work that depends on Chris's context. The goal is a better decision
or artifact with less supervision, not maximal reading or personal-data collection.

## Choose the owner
| Question | First source |
|---|---|
| Active work, status, next action | Governed project/task registry, then linked source |
| Decisions and Monday working agreements | monday Decisions/ and relevant checkpoint |
| Personal context, preferences, prior thinking | personal curated notes; get_personal_context only when relevant |
| Professional work, experience, source decks | professional; preserve confidentiality and source records |
| Books and future concepts | gw Hopper for ideas; owning manuscript for content; registry for active work |
| Freedom and portfolio strategy | retirement; plans do not authorize financial actions |
| Family history | family_tree; preserve Proven / Probable / Blocked evidence grades |
| Actual timing | Outlook work, Cozi family, approved personal calendar; distinguish mirrors |

## Retrieve, resolve, apply
1. Identify which missing facts could change the answer. Start with exact
   project/person/artifact terms in the owning vault. Avoid scanning all vaults
   or reading the private log for routine technical work.
2. For conceptual questions or weak exact results, use semantic search scoped
   to the relevant vault. Keep unreviewed corpus excluded by default. Explicit
   research into original source material may include it, labeled unreviewed.
3. Read the best source notes in full. Follow relevant links to the decision,
   evidence, or artifact they depend on. Two or three decisive notes often
   suffice; expand when evidence conflicts or the stakes warrant it.
4. Distinguish the event/evidence date from file modification and retrieval.
   An old stable preference may remain useful; an old release status requires
   current evidence. Do not infer avoidance from note age or turn corpus text
   into a confirmed personal fact.
5. If sources disagree, retain both provenance chains and identify what would
   settle the conflict. Prefer a direct, later owner statement over an older
   summary when they address the same question; explain the change.
6. Apply the context to the actual result. Do not display private history to
   demonstrate recall. Cite the source path for material vault claims.
7. When authorized work changes an operational fact, update its owning record,
   then any affected derived plan. Read the write back. Do not create a second
   backlog or silently promote unreviewed biography.

## Missing or stale retrieval
A scheduled preparation run may refresh the existing derived semantic index
with `sync_semantic_index` before conceptual retrieval. Prefer incremental sync;
do not rebuild the corpus casually. If a refresh is already running, avoid a
second writer and use keyword search plus direct reads until it completes.
A failed refresh must remain visible and must not be described as current.

A search miss is not proof the information does not exist. Try one useful
alternate term or conceptual query; inspect source location and index health
when the named artifact is known to exist. A semantic "ready" status proves
availability, not freshness or recall quality. Compare results with keyword
search and direct source reads. Report unavailable connections specifically.
Do not ask Chris to supply an accessible artifact before looking for it.

## Completion check
Can the response identify the source, explain how it changes the result, and
name remaining uncertainty without a biography dump? If yes, stop retrieving
and do the authorized work. More notes are not inherently better.

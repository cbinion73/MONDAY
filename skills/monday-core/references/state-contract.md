# Monday state contract

Keep every category in its owning system. Cross-surface work references the
owner; it does not create a competing copy.

| State | Owner | What Monday may retain or pass |
| --- | --- | --- |
| Stable personal preferences and relationship context | ChatGPT native memory | Cautious, durable facts and corrections |
| Current asks, decisions, follow-ups, waiting-on items, project context | Monday operational vault | Concise WHAT / WHY / NEXT record with owner and status |
| Dates, deadlines, reminders, availability | Calendar or reminder system | Event/reminder link or identifier, never a shadow schedule |
| Background, history, evidence, medical records, project knowledge | Subject-specific authoritative vault/knowledge store | Source-aware synthesis and links to the owner |
| Local technical artifacts and execution evidence | Repository, local workspace, or approved bridge | Exact path, result, verification, and next decision |
| Credentials, tokens, calendar feed URLs, and private keys | Local secret storage only | Nothing in chat, memory, handoff packets, or vault notes |

Apply the no-orphan rule: a time-bound commitment must have a real calendar or
reminder trigger. Apply the aging rule: after about 30 days, deliberately
promote, archive, recommit, or delete temporary operational state.
